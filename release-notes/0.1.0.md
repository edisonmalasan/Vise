# Vise Transcoder 0.1.0

The first release. Everything below was built and checked by the release
workflow; the three installers attached to this release are the exact
artifacts that workflow produced and verified.

## Highlights

- **The window is a shell, not a document.** The name and the controls that
  open the other windows are a bar at the top; the theme and the layout
  direction are one line of switches under it; the work is three bands in the
  order the task happens; and the output path and the button that uses it are
  pinned to the foot of the window. The one thing you came to do is never
  something you have to scroll back to find.
- **The pipeline never runs inside the window.** A separate worker process
  serves a token-authenticated loopback API, so a long encode never freezes
  the interface and an encoder crash costs one job rather than the session.
- **Every build carries its own encoder.** The media tools are pinned per
  platform by archive digest and by binary digest, and every build checks
  those digests before it trusts what it downloaded.
- **138 built-in presets** across six categories, each resolved against the
  hardware this machine actually has. A preset that cannot run stays in the
  list with the reason beside it rather than disappearing.
- **Six languages and a right-to-left layout**, switchable at run time, with a
  fallback chain that never shows a raw key.

## Platforms

| Platform | File | Architecture |
|---|---|---|
| Windows | `Vise Transcoder_0.1.0_x64-setup.exe` | x86-64 |
| Linux | `Vise Transcoder_0.1.0_amd64.deb` | x86-64 |
| Linux | `Vise Transcoder_0.1.0_amd64.AppImage` | x86-64 |
| macOS | `Vise Transcoder_0.1.0_aarch64.dmg` | Apple silicon |

`SHA256SUMS` carries the digest of every file above.

## Known issues

- **The macOS encoder needs Rosetta 2.** The only macOS build of the encoder
  that is published is the x86-64 one, so the application on Apple silicon
  runs it through Rosetta 2. It ships and it works, but a Mac without Rosetta
  installed cannot use the bundled encoder and will fall back to the machine's
  own.
- **There is no macOS build for Intel.** The application is built on Apple
  silicon, so the bundle is aarch64 and does not run on an Intel Mac.
- **Optical discs have not been read from a physical disc.** The disc is
  recognised, the demuxer is chosen, the reader is reached, and the refusal
  path was exercised, but no physical disc was available to decode.

## Verification

- `cargo test --workspace` — the whole suite, on every run
- `cargo clippy --workspace --all-targets -- -D warnings` — clean
- `cargo fmt --all -- --check` — clean
- The Windows installer was installed into a scratch directory and its tree
  inspected: the application, the worker, and both tools are present, and the
  installed worker answers its own authenticated API.
- The Linux package was unpacked and its parts run, and the media tools in it
  were executed rather than merely listed.
- The macOS bundle and disk image were produced on a macOS machine, and the
  media tools in it were checked against the pin file.
